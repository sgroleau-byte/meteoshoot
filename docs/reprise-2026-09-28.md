# MeteoShoot: point de reprise au 28 septembre 2026

Document de passation pour reprendre le travail dans une nouvelle conversation. Tout ce qui est décrit ici
est local: rien n'a été poussé sur GitHub, rien déployé sur Vercel, rien envoyé sur les boutiques.

## En bref

MeteoShoot (planificateur de tournages selon la météo: site web PWA sur Vercel, données Supabase,
abonnements Lemon Squeezy, cartes Google Maps) est maintenant compilé par Vite et emballé en apps natives
iPhone et Android avec Capacitor. L'app iPhone est installée sur l'iPhone de Stéphane et validée par lui.
L'app Android tourne dans l'émulateur (pas encore testée sur un vrai téléphone). La version web pour Mac
et Windows reste la même base de code. Objectif: des clients payants dans les prochains mois.

### Ouverture de l'app et animations « premium »

Séquence actuelle (mesurée sur le web et dans le simulateur, identique dans l'app):

| Instant | Ce qui se passe |
|---|---|
| 0 à 2,0 s | logo et halo vert animés (dérive 7 s, respiration 2,8 s), interface retenue |
| 2,0 à 3,4 s | le rond turquoise du logo (image `splash-o.png`, élément `.splash-flare`) grandit sur place, lentement puis très vite (progression en t³, échelle finale calculée selon l'écran), jusqu'à sortir de l'écran; typo, sous-titre, version et halo s'effacent entre 2,5 et 3,0 s; l'interface se met en place sous le voile sombre |
| 3,4 à 3,9 s | le voile sombre se dissout sur l'interface déjà en place |
| 3,9 s | tout en place |

- Fichiers: `index.html` (séquence: `grow()` anime le rond par `element.animate`, classe `splash-grow`, puis
  `splash-hidden`; racine `#root.ms-hold`, événement `meteoshoot:reveal`), `src/styles/app.css` (`splash-grow`
  efface le reste du splash, `#root.ms-hold` met en pause les animations d'entrée), `src/utils/entrance.js`.
- Décisions validées par Stéphane, à ne pas « corriger »: le logo reste au moins 2 s; le halo bouge tout le
  temps; c'est le rond turquoise du logo, déjà animé, qui grandit (« il n'y a pas de nouvel élément à ajouter,
  pas de nouveau rond »); les données apparaissent après, pas pendant; entrée des cartes en cascade, carte de

- Variantes rejetées le 28 septembre: le gros halo vert (en haut à gauche) agrandi jusqu'à remplir l'écran
  (« ça ne fait pas du tout ce que je veux »), puis un anneau dessiné en CSS partant du halo ou du rond
  (« il n'y a pas d'anneau »). Ne pas y revenir.
- Réglages à valider avec lui sur l'iPhone: durée du grandissement (1,4 s), moment où le reste du splash
  s'efface, durée de la dissolution (0,5 s).

## Comment travailler

### Commandes

```bash
npm run build          # produit dist/ (clé Google web)
npm run build:native   # dist/ avec la clé Google native (MS_TARGET=native)
npm run lint           # variables non déclarées
npm run cap:sync       # build natif + synchronisation ios/ et android/
tools/iphone-install.sh 03E280FB-4FB2-5EE8-B543-2C335928D8A0   # iPhone branché ET déverrouillé
tools/android-run.sh   # émulateur + installation + lancement
```

- Après `tools/iphone-install.sh`, `dist/` est recompilé et `dist/tools` disparaît: pour les tests web,
  refaire `rm -rf dist/tools && mkdir -p dist/tools && cp -R tools/baseline dist/tools/baseline`.
- Ne pas relancer l'app sur l'iPhone depuis le Mac pendant que Stéphane s'en sert (ça la ferme).
- Ne jamais commettre `dist/`, `build/`, `.claude/`.

### Tests web avec le harnais

- Serveur `meteoshoot-dist` (port 8642, sert `repo/dist`) dans le launch.json du dossier parent
  `_METEOSHOOT`. Outil chrome-devtools MCP: `navigate_page` avec un `initScript` qui charge
  `/tools/baseline/harness.js` de façon synchrone (XMLHttpRequest puis eval).
- Le harnais sème 12 faux projets, une fausse session Supabase et la permission de position, rejoue des
  réponses météo enregistrées, fige la date et la géolocalisation, puis expose `window.__bl.marks`
  (rootRendered, firstDayCell, splashHidden, splashRemoved) et `window.__bl.halo` (échantillons toutes les
  100 ms pendant 5 s: échelle du halo, opacité du voile, retenue, opacité carte, nav et carte de position).
- Pour inspecter une image fixe de l'ouverture: dans l'initScript, neutraliser `__meteoshootReady` (setter
  qui avale l'assignation) et le filet de 7 s, puis ajouter `splash-bloom` avec `animation-delay` négatif et
  `animation-play-state: paused`, ou piloter `document.getAnimations()` (`pause()` puis `currentTime`).
- Mesures de référence et captures: `../verification_etape0/` (avant/après, perf, sécurité, simulateur,
  Android).

## Procédure de mise en production (quand Stéphane dit « pousse »)

1. Bumper la version aux trois endroits: `index.html` (splash), `src/components/PreferencesView.jsx`,
   `public/sw.js` (`CACHE_VERSION`).
2. `npm run lint && npm run build` sans erreur.
3. Avancer `dev` sur `etape0-vite` (`git checkout dev && git merge --ff-only etape0-vite`), puis:

```bash
git -c credential.helper= -c credential.helper='!gh auth git-credential' push https://github.com/sgroleau-byte/meteoshoot.git dev
```

   et la même commande avec `dev:main` pour la production.
4. Surveiller le premier déploiement Vercel avec Vite (`vercel.json` déclare `npm run build` et `dist`),
   puis vérifier la mise à jour d'une installation existante (double chargement connu et voulu).
5. Reconstruire les apps natives (`npm run cap:sync`) après tout changement web.
